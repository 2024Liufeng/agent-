## 应用形态与本地部署说明

本项目的前后端版本首先做成本地 Web 应用，不优先打包成 `.exe`。用户启动项目后，由本地服务提供网页和 API，随后使用浏览器访问本地地址。

```text
启动项目
   ↓
FastAPI 启动本地后端服务
   ↓
Vue 前端由开发服务器提供，或由 FastAPI 提供构建后的静态文件
   ↓
浏览器打开 http://127.0.0.1:8000
   ↓
Vue 页面调用 FastAPI API
   ↓
Agent 调用 RAG、Memory 和 DrissionPage 浏览器工具
```

### 推荐技术结构

```text
前端：Vue 3 + TypeScript + Vite
UI：Ant Design Vue
后端：FastAPI
通信：REST API + SSE
Agent：HelloAgents
浏览器自动化：DrissionPage + Chromium
部署：本地 Docker
```

Vue 前端负责用户输入、任务状态、平台报价表格、证据展示和推荐结果；FastAPI 负责接收请求、调用 Agent 并返回结构化结果；SSE 用于将 Agent 的执行进度实时推送给前端。

DrissionPage 和 Chromium 也可以放入本地 Docker。浏览器 Profile 通过 Docker volume 持久化，第一次启动时用户在浏览器中完成淘宝、京东和拼多多登录，后续运行复用登录会话。

本地 Docker 与云服务器的网络条件不同。本地 Docker 通常通过宿主机网络访问平台；如果以后部署到云服务器，出口 IP 会变成云服务器 IP，需要重新评估平台登录、会话和访问限制。

### 为什么先使用本地 Web 应用

- 前端和后端职责清晰，便于调试和扩展。
- 浏览器登录、Profile 和 DrissionPage 运行在用户自己的环境中。
- 可以先验证 Agent、页面交互和完整业务流程。
- 后续可以继续部署到云端，或拆分为云端 Agent 服务和本地浏览器 Worker。

`.exe` 打包可以作为后续分发方式，但不是当前实现前后端应用的必要条件。

## 前后端交互设计与实现约定

### 页面布局

页面是一个本地 Web 工作台，核心交互是对话框。用户用自然语言描述购物需求，主 Agent 在执行过程中可以继续提问；用户的回答通过同一个对话框返回。页面分成四块：

1. 顶部显示当前运行状态和京东、淘宝、拼多多的会话状态。
2. 中间左侧是对话区，显示用户消息、Agent 回答、需要用户确认的问题和重新登录提示。
3. 中间右侧是实时进度区，显示 Agent、子 Agent 和浏览器工具的开始、完成、异常事件。
4. 底部或右侧显示结构化结果、报价、推荐理由和证据链接。

页面只需要一个自然语言输入框和发送按钮。登录失效时，页面显示对应平台的“在本机 Edge 中重新登录”操作；登录完成后用户在对话框中发送“继续”，任务从原状态恢复。

### 后端接口

```text
GET  /api/health                         健康检查
GET  /api/platforms/status               读取本地 Profile 和平台状态
POST /api/platforms/{platform}/login    打开可见浏览器，指导用户登录
POST /api/tasks                          创建购物任务
GET  /api/tasks/{task_id}                 查询任务快照
GET  /api/tasks/{task_id}/events         SSE 订阅实时事件
POST /api/tasks/{task_id}/messages        发送追问回答或补充需求
POST /api/tasks/{task_id}/resume          从等待状态继续任务
```

任务接口只负责会话和事件编排，实际购物决策仍由 `ShoppingAssistantService` 完成。服务调用放到后台线程，避免 DrissionPage 或模型调用阻塞 FastAPI 的事件循环。

### SSE 事件格式

每条事件都包含 `id`、`task_id`、`type`、`timestamp` 和 `data`。当前事件类型为：

```text
progress              普通进度文字
tool_started          子 Agent 或平台工具开始
tool_completed        工具完成并附带摘要
assistant_delta       Agent 回答增量，前端按顺序拼接
user_input_required   主 Agent 需要用户补充信息
auth_required         某个平台需要重新登录
completed             任务完成，data 中包含最终结果
failed                任务失败，data 中包含可读错误
```

前端收到 `assistant_delta` 时追加回答文本；收到 `progress`、`tool_started` 或 `tool_completed` 时追加进度；收到 `user_input_required` 或 `auth_required` 时把输入框切换成可继续对话的状态。这样模型回答和后端进度都可以逐步显示，主 Agent 也可以在任务中途等待用户。

### 本地启动

```powershell
cd C:\Users\dummy\PycharmProjects\agent-\自己项目\helloagent-project
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

开发前端时另开终端运行 `cd frontend; npm install; npm run dev`，页面通过 `VITE_API_BASE_URL` 访问 FastAPI。生产构建后执行 `npm run build`，FastAPI 会自动提供 `frontend/dist` 中的静态文件。
