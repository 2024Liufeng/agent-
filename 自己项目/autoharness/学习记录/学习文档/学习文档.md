## 项目阅读顺序检查

以 commit `6bb7ea5` 为准，项目仓库没有提供一套明确的源码阅读顺序或学习路线。README 介绍了项目定位、配置、工作方式和演示流程，但没有规定应该先读哪些源码文件。

因此采用下面的连续分段方式学习：每一段都承接上一段，先建立整体地图，再沿着一个 skill 的完整生命周期阅读实现，最后用测试验证理解。README 学习阶段以 `repo2-中文/README.md` 为主要阅读材料，严格按照原 README 的章节和段落顺序推进；中文副本保持原文结构和含义，遇到翻译不确定处再对照 `repo2/README.md`。学习过程中先讨论和确认项目实际行为，不立即把内容整理成最终学习指南；全部流程理解后，再汇总成完整版本。

每个阶段文档采用“原文片段 → 对应补充”的交替方式：

1. 保留一段对应的中文版 README 或源码文档原文，方便回看和核对。
2. 紧接着解释这一段的含义，并补充已经从源码、配置或测试中核对过的实现细节。
3. 再进入下一段原文；如果原文是一张表，就按表格中的概念逐项补充。

## 学习记录的强制执行规则

1. **先写入，再继续**：一个阶段或一个已完成的学习分段讲完后，必须先把本次对话中已经贴出的内容写入对应阶段文档，并检查文件存在，再开始下一段学习。不能因为准备继续而跳过写入。
2. **原样保留**：阶段文档中的正文直接复用本次对话已经贴出的“原文片段”和“补充”，只允许增加标题、分隔线和必要的文件结构，不重新压缩或改写已经看过的内容。
3. **英文术语格式**：凡是为了理解而保留的英文术语，都使用 `English（中文意思）` 格式。第一次出现时必须加中文释义；后续仍保留该格式，不能只留下英文。代码、路径、变量名、命令和文件名按原样保留，不强行翻译。
4. **写入后复核**：写入后检查阶段文件路径、文件内容开头和结尾，并确认原项目文件没有被修改。

分成多个阶段后，直接保留原文不会造成单个文档过大。把补充放在对应原文下面，可以让每个概念就地解释，减少在原文和说明之间来回查找。README 全部读完并形成整体理解后，再进入 `src/`、`agents/` 和测试，继续沿着同一条 skill 生命周期展开。

### 第 9 段：用测试验证完整流程

最后把关键测试与前面的流程对应起来，验证下面这条完整链路：

```text
Stop
→ 捕获会话窗口
→ 启动 Reflector
→ stage_skill 追加 intent
→ Promoter 读取 intent
→ validate
→ 写入 skill
→ 记录 sidecar、ledger 和 evidence
→ 后续会话记录使用情况
→ SessionStart 执行生命周期判断
```

## 为什么采用这个顺序

这个项目是事件驱动的，流程跨越 Hook、后台子会话、MCP server、intent 队列和文件状态。按目录逐个阅读，容易只理解单个函数，难以看清一次 skill 从创建到退役的连续变化。

先看 README 可以建立术语和角色地图；再沿着一条真实生命周期阅读，可以把多个目录连接起来；最后用测试验证，可以区分设计规则、实现细节和故障安全行为。这样最终得到的是一份从触发、提案、校验、落盘、使用到归档的完整理解。
