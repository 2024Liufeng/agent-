# autoharness 整体设计

> 本文从系统设计角度理解 autoharness。  
> 学习文档记录我们看过的内容和学习过程；阶段文档保存原文片段与补充；本文说明这些内容如何共同组成一个完整的 skill 生命周期。

---

## 一、总体设计

### 1. 项目目标

autoharness 在 Claude Code 旁边增加一个自学习 skill 层。

它不重新训练模型参数，而是从真实工作中提炼可复用经验，将经验保存为 skill，并在后续会话中继续提供给模型。

```text
真实工作
  ↓
发现可复用经验
  ↓
形成 skill
  ↓
后续会话召回和使用
  ↓
根据使用情况继续维护
```

### 2. 一个 skill 的完整生命周期

```text
真实工作
  ↓
CAP · capture（捕获）
  ↓
达到工具调用阈值
  ↓
REF · reflect（反思器）分析 episode（学习片段）
  ↓
生成 intent（提案）
  ↓
Promoter · promoter（提案落地器）校验
  ↓
写入 SKILL.md 和附属文件
  ↓
记录 sidecar（附属计数）和 ledger（账本）
  ↓
后续会话建立索引并召回
  ↓
记录 use（使用）、view（查看）、patch（修改）
  ↓
毕业、合并、归档或恢复
```

### 3. 主要设计原则

#### 3.1 提案和写入分离

```text
REF：分析经验，提出 intent（提案）
Promoter：检查 intent，真正写入文件
```

Reflector 不能直接修改 skill 文件。这样可以把模型的判断和实际文件操作分开。

#### 3.2 规则和证据分离

```text
SKILL.md：保存下一次会话可执行的长期规则
ledger：记录为什么创建或修改
evidence：保存支持规则的脱敏会话证据
sidecar：保存生命周期计数
```

规则正文不混入维护历史，避免影响后续召回。

#### 3.3 真实工作触发学习

学习不是由固定计时器或常驻后台服务启动，而是由会话中的实际工具调用触发。

#### 3.4 只管理自己创建的内容

带有 autoharness ledger 标记的 skill 才会被 Promoter 和生命周期管理器处理。

手工创建或外部安装的 skill 不会被自动修改、归档或删除。

## 二、阶段一具体设计：README 建立架构地图

### 1. 阶段目标

阶段一回答：

```text
系统由哪些角色组成？
这些角色如何连接成一条学习流水线？
```

### 2. 组件分工

| 组件 | 设计职责 |
|---|---|
| CAP · capture（捕获） | 捕获会话内容、工具输入输出，并统计工具调用 |
| REF · reflect（反思器） | 分析 episode，提出 skill 创建或修改方案 |
| Promoter · promoter（提案落地器） | 校验 intent，并作为唯一写入者 |
| IDX · surface（索引展示） | 在会话开始时让模型看到 autoharness skill |
| MNG · lifecycle manager（生命周期管理器） | 统计使用情况并管理 skill 生命周期 |
| LED · ledger（账本） | 记录创建、修改和证据 |
| curator · curator（整理者） | 定期合并和维护整个 skill 库 |

### 3. 阶段一得到的主流程

```text
CAP
  ↓
REF
  ↓
Promoter
  ↓
IDX
  ↓
MNG
  ↓
LED
  ↓
curator
```

阶段一只建立角色地图，不负责解释每个角色的具体代码实现。

### 4. 阶段一和阶段二的连接

README 告诉我们：

```text
有哪些组件，以及它们各自负责什么
```

阶段二继续回答：

```text
这些组件操作哪些数据对象？
这些数据对象如何保存？
```

## 三、阶段二具体设计：skill 数据模型

### 1. 阶段目标

阶段二要建立的设计是：

```text
一个 skill 不只是一个 SKILL.md 文件，
而是由格式、层级、存储、计数、账本和提案队列共同组成。
```

### 2. 阶段二文件如何共同构建设计

```text
format_spec.md
  ↓ 定义合法 skill 的格式
layer.py
  ↓ 定义 skill 属于哪一层
skill_store.py
  ↓ 定义 skill 如何存放和操作
sidecar.py
  ↓ 定义当前使用和生命周期计数
ledger.py
  ↓ 定义变化原因和证据历史
intent_queue.py
  ↓ 定义提案如何等待处理
```

---

### 3. `format_spec.md`：定义格式契约

状态：已学习。

它规定：

- `SKILL.md` 的 frontmatter（文件头元数据）；
- `name`、`description`、`category` 的要求；
- description（描述）如何作为触发器；
- 正文高度限制；
- 附属文件白名单；
- 路径安全规则；
- 内容完整性；
- global（全局层）和 project（项目层）的差异。

它解决的问题是：

```text
什么样的内容才有资格成为 skill？
```

---

### 4. `layer.py`：定义作用范围

状态：待学习。

它需要解释：

```text
skill 属于当前项目，还是所有项目？
```

重点关注：

- project（项目层）如何表示；
- global（全局层）如何表示；
- 两层目录在哪里；
- 如何根据层级选择数据目录；
- 两层的限制如何体现。

它和 `format_spec.md` 的关系是：

```text
format_spec.md：规定内容是否合法
layer.py：规定内容属于哪个作用范围
```

---

### 4. `layer.py`：定义作用范围

状态：已学习。

`layer.py` 是 skill 路径和层级的安全边界。它不负责读取或修改 skill 内容，而是负责把：

```text
layer（层级）
+ skill name（名称）
+ subfile path（附属文件路径）
```

转换成安全的磁盘路径。

#### 4.1 层级模型

系统只允许两个层级：

```text
global（全局层）
project（项目层）
```

其他层级会在进入路径计算前被拒绝。

```text
global  → ~/.claude/
project → 主工作树/.claude/
```

#### 4.2 项目层的 Git 工作树处理

普通项目使用当前工作目录作为项目身份。

如果当前目录是链接的 Git worktree（工作树），`layer.py` 会通过：

```text
git-dir（当前工作树目录）
git-common-dir（仓库共享目录）
```

识别它，并把路径重新映射到主工作树根目录。

这样同一个仓库的多个工作树会共享：

- skill；
- intent；
- 计数器；
- autoharness 状态。

如果 Git 判断失败，则回退到当前工作目录，不猜测其他仓库位置。

#### 4.3 skill 名称安全

skill 名称必须：

- 是字符串；
- 以字母或数字开头；
- 只能包含字母、数字、点、下划线和连字符；
- 不能包含 `..`。

新建名称还必须：

- 不超过 100 个字符；
- 不能以点结尾；
- 不能使用 Windows 保留名称。

读取旧名称时检查较宽松，创建新名称时检查更严格，以兼容旧数据并保护新数据。

#### 4.4 skill 目录模型

```text
.claude/
├── skills/
│   ├── <skill-name>/
│   └── .archive/
└── autoharness/
```

其中：

```text
skills_dir()  → 活动 skill 目录
archive_dir() → 归档目录
state_dir()   → autoharness 状态目录
symbol_dir()  → 某个具体 skill 目录
```

`root` 参数允许测试或调用方显式指定根目录；没有指定时使用层级默认根目录。

#### 4.5 附属文件路径安全

附属文件只能位于四个目录：

```text
scripts/       脚本
templates/     模板
assets/        静态资源
references/    参考资料
```

路径必须：

- 是相对路径；
- 至少包含目录和文件两段；
- 使用 `/`；
- 不能包含 `..`；
- 不能包含反斜杠；
- 第一段必须属于白名单；
- 每一段都必须是安全名称。

证据文件使用：

```text
references/evidence-*.md
```

#### 4.6 `layer.py` 和后续文件的关系

```text
layer.py
  ↓ 提供安全的层级和路径
skill_store.py
  ↓ 使用这些路径读写和归档 skill
sidecar.py / ledger.py
  ↓ 在对应层级保存状态和历史
intent_queue.py
  ↓ 在对应层级保存待处理提案
```

所以，`layer.py` 是阶段二数据模型的路径基础设施。
