# Spider Agent 架构设计

## 目标和范围

接收网站栏目和目标字段，试采可核对的公告样本，保存全过程，等待人工审核。试采可按用户要求写入指定 MySQL，供甲方审核；审核通过后允许按已审核配置继续采集，先导出 JSON。首个站点是易联供应链平台；其他站点以后通过适配器扩展。

## 流程

```text
任务配置 → 单一编排流程 → 逐栏目试采 → 自动校验 → 报告与可选试采入库
                    ↓                    ↓
                  Trace             待人工审核
                                         ↓
                              审核通过后继续采集 → JSON
```

一个任务包含多个子栏目，每个栏目分别报告 `sampled`、`empty`、`failed` 或 `unverified`。空列表不是成功采到数据；失败不能当成空列表。历史接口只是候选，必须通过运行验证，不能把缺失栏目伪称已覆盖。

## 职责划分

| 模块 | 职责 |
| --- | --- |
| `cli.py` | 创建试采、查看、审核和继续采集的命令入口 |
| `workflow.py` | 单一编排：管理任务状态、调用站点适配器、校验、保存报告 |
| `sites/elink.py` | 易联请求和原始字段提取；后续每个站点实现相同接口 |
| `validation.py` | 字段、URL 和正文质量检查，未知业务字段明确标记 |
| `storage.py` | 本地任务文件、审核记录和 JSONL Trace |
| `advisor.py` | 可选的单一审核 Agent，通过只读工具获取试采摘要并给出关注点，不决定审核 |
| `database.py` | 对试采样本进行业务映射、去重、事务写库并记录入库结果 |
| `config/elink.json` | 栏目清单和候选接口，可直接修改和审阅 |

当前实现是确定性工作流 + 可选单 Agent 审核建议；Agent 仅能调用读取试采摘要的只读工具。尚未实现模型自主探测与代码生成，不具备通用自动接站能力。

## 任务和审核

每次试采创建独立 run 目录，保存配置快照、报告、样本及 trace。`review` 必须指定审核人、备注和批准/驳回；批准绑定配置与试采报告的 SHA-256，后续运行前重新校验。只有全部目标栏目有有效样本、所有样本基础校验通过时才可批准；零数据、未验证或失败需要先处理。审核是持久状态，不依靠模型记忆。

继续采集需要显式提供页数上限，按审核快照重复抓取并按来源 ID 去重，写入独立 JSON 文件。单条失败或后续栏目失败写入错误报告；它不代表已完成全量采集。每条数据保留来源栏目、详情 URL、标题、时间、正文、来源 ID；分类和地区未证实时留空，不能猜。

## Trace 与数据

每个 run 的 `trace.jsonl` 保存时间、run_id、步骤、状态、耗时与简要详情；栏目和每条失败可追踪。模型输入仅为摘要，不能包含密钥；不记录 token、cookie、授权头或完整正文。报告和样本独立保存；样本可包含源站正文，请注意本地访问权限。

字段以来源和业务约定为准：`collect_id` 为详情 URL，`from_site` 为栏目页，`release_time` 为原始发布时间，`content` 为规范字体后的正文 HTML。试采入库使用已知栏目分类；地区从招标人名称或地址提取，找不到按旧业务资料兜底北京市，并在入库报告标记来源，需人工确认。附件处理及完整地区规则仍待实现。来源页面 URL 目前可能是大栏目入口，需要人工确认。

## 设计边界

- 默认仅用标准库请求已知的公开接口，不绕过验证码；遇到验证或变化时记录失败并人工处理。
- `trial --write-db` 或 `stage-db` 会实际写入环境变量指定的库；试采写库不等于审核通过。正式批量采集不自动写库、部署或删除数据。
- 目前易联接口是历史参考，使用前需实时验证。未知站点需要增加适配器；目前不支持任意网页自主建站。
- 文件存储适合单用户本地试用，尚无多进程并发控制、认证、数据库事务和生产调度。
- 后续优先做：浏览器探测工具、字段及地区业务规则、自动回归样本、测试库适配、增量调度、再评估是否需要多智能体。
