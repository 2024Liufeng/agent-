# SpiderAgent 手机工作台设计

设计稿于 2026-11-02 确认，以浅色界面作为本轮实现目标：

- [日常对话](daily-use.png)：手机聊天、执行过程、历史抽屉和工作区切换。
- [目录与设置](settings.png)：服务器目录浏览、模型设置、高级运行选项和项目偏好。

## 页面与交互

- 页面使用浅色配色、系统中文字体、统一 SVG 图标和至少 44px 的触控目标。当前版本没有主题切换器或底部导航。
- 顶栏左侧打开可收起的历史抽屉，中间切换工作区，右侧提供唯一的新建会话入口。模型选择只在输入框内。
- 历史按今天、昨天和更早分组，并随当前工作区筛选。切换会话后抽屉关闭；遮罩和 Escape 键也能关闭抽屉或设置面板。
- 输入框显示当前真实模型。运行任务时可以补充要求，也可以停止任务。模型、思考档位、Fast 和高级运行选项由服务端能力目录与会话设置提供。
- 工作区面板显示最近工作区及各自的设置入口。目录面板通过服务器目录 API 浏览根目录、面包屑和子目录；只有确认“使用此目录”后才创建工作区。
- 项目偏好保存到指定工作区；不同会话保留各自的对话和运行设置，同时共享所属工作区的文件。
- 助手内容使用 Markdown 渲染并经 DOMPurify 清洗。连续工具调用合并为默认折叠的执行过程卡片；展开后显示步骤、状态和可选的原始输出。

## 数据与状态原则

参考图中的消息、模型和活动只用于表达布局，不作为产品数据。模型清单、连接状态、任务状态、目录和工作区信息均读取服务端。用户消息按纯文本显示；助手 Markdown 清洗后才进入页面。流式刷新保留执行过程的展开状态、滚动位置和输入焦点。

服务器目录选择使用 `GET /api/directories?path=绝对路径`；添加工作区只在用户确认后调用 `POST /api/workspaces`。项目偏好请求必须携带目标工作区 ID，避免齿轮入口写入其他工作区。

## 验收记录

- Playwright + Edge 在 `320×700`、`390×844`、`768×1024` 三种尺寸完成浏览器验收：96 项通过，0 项失败，0 条控制台错误。覆盖页面溢出、历史与工作区切换、目录浏览与确认、模型草稿往返、设置保存、XSS 样例、SSE 更新以及焦点和滚动保持。
- `npm run check` 通过。隔离验收不发送真实模型消息，也不修改正式项目偏好。
- 本机 Codex 服务真实对话和模型目录已验证；模型目录返回 8 个模型。
- 先前的开发记录显示 DSH ACP 曾创建会话并连续完成两轮任务。最近一次复测使用 60 秒启动上限，返回“DSH 连接已关闭”；项目默认启动上限为 180 秒，因此这次复测不能判定 DSH 当前不可用。下一轮应按默认上限重新验证。
- 云服务器尚未部署。本机和隔离浏览器验收不能替代目标服务器上的登录、进程和网络检查。

验收报告与截图保存在被忽略的 `codex-web/.data/light-redesign/` 本地目录；它们不包含在仓库提交中。

## 后续维护

保持顶栏只有一个新建入口、输入框只有一个模型入口。目录选择必须经过 API 和明确确认；工作区偏好必须按目标 ID 保存。新增状态和提示应依据服务端返回，不要用参考图里的示例数据模拟成功。
